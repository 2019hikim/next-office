# 이음오피스 기반 한글 문서 에디터 초기 설계

2026년 11월 3일 · v1 · 소스 검토를 바탕으로 한 설계안

## 1. 개발 가능성과 출발점

**이음오피스에서 한글 문서 편집 기능을 분리해 독립 데스크톱 앱으로 개발할 수 있다.** 저장소에는 한글 편집기만 Electron 창으로 여는 진입점이 있다. 빈 A4 문서에 한국어 한 문단을 입력하고, HWP와 HWPX로 각각 내보낸 뒤 다시 열어 본문이 일치하는지 확인하는 테스트도 있다. 이번 검토에서 확인한 범위는 공개 소스와 테스트 코드까지다. 아래 R1~R5는 새 독립 앱에서 직접 검증할 기준이다. [한글 전용 창 진입점](https://github.com/pblsketch/openoffice/blob/af65e7a0e36b7536504695d9a46449da070a578c/apps/hwp/src/main/hwp-main.ts#L974-L1019) · [빈 문서 작성·저장 테스트](https://github.com/pblsketch/openoffice/blob/af65e7a0e36b7536504695d9a46449da070a578c/apps/hwp/tests/blank-document.test.ts#L20-L54)

## 2. 첫 제품의 범위

| 항목 | 설계안 |
|---|---|
| 프로젝트 이름 | 한글 문서 에디터(가칭) |
| 목적 | 교사가 한 쪽짜리 수업 안내문을 작성해 학생이 한컴 한글에서 열 수 있는 파일로 전달한다. |
| 첫 사용 장면 | 빈 A4 문서를 열고 제목 한 줄과 본문 두 문단을 입력한다. `수업안내.hwpx`로 저장하고 앱을 닫은 뒤 다시 연다. |
| 첫 버전 | Windows용 단일 창에서 문서 한 개를 다룬다. 한글 입력·수정, HWPX 열기, 다른 이름으로 저장, 미저장 문서 닫기 확인을 제공한다. |
| 후속 개발 | HWP 저장과 호환성 검증, 제목 서식, 표가 들어간 활동지 제작 순으로 확장한다. |
| 초기 범위 밖 | AI 대화, 다른 오피스 편집기, PDF 변환, 클라우드 동기화 |

첫 저장 형식으로 **HWPX**를 선택한다. 저장 전후의 본문이나 문단이 다르면 파일 내부 XML에서 어느 부분이 달라졌는지 확인할 수 있기 때문이다. 기존 엔진에는 HWP 출력 경로도 있으므로, 두 번째 형식을 추가할 때 별도의 호환성 기준을 세운다. [형식별 저장 구현](https://github.com/pblsketch/openoffice/blob/af65e7a0e36b7536504695d9a46449da070a578c/apps/hwp/src/renderer/save-flow.ts#L129-L163)

## 3. 재사용할 구성과 독립 앱에서 할 일

| 구성 | 재사용할 부분 | 독립 앱에서 할 일 |
|---|---|---|
| 문서 엔진 | 이음오피스가 한글 문서 조판과 저장을 보정한 `vendor/rhwp-core` | 시제품에서는 엔진과 패치를 검토한 버전으로 고정한다. |
| 편집 화면 | `rhwp-studio`와 빈 A4 한 쪽을 불러오는 초기화 코드 | 한국어 입력기로 글자 조합, 줄바꿈, 지우기, 실행 취소를 확인한다. |
| 파일과 창 | 한글 전용 Electron 창, 파일 읽기·저장 통로, 저장 전 형식 검사 | 새 문서·열기·다른 이름으로 저장 메뉴와 미저장 문서 닫기 확인을 독립 창에 연결한다. |
| 패키징 | 저장소의 한글 모듈 개발용 실행 명령과 스튜디오 빌드 설정 | 필수 공용 패키지와 자산을 확인하고 한글 전용 Windows 배포 설정을 만든다. |

먼저 원본 저장소에서 단독 창을 실행해 정상 동작의 기준을 잡는다. 그런 다음 같은 문서로 비교하면서 AI 패널 등 첫 버전에서 쓰지 않는 연결을 분리한다. `apps/hwp`가 공용 UI·언어·Electron 유틸리티와 패치된 엔진을 참조하기 때문에 폴더 하나를 복사하는 것만으로는 독립 패키지가 완성되지 않는다. [한글 앱 의존성과 개발 명령](https://github.com/pblsketch/openoffice/blob/af65e7a0e36b7536504695d9a46449da070a578c/apps/hwp/package.json) · [패치된 엔진](https://github.com/pblsketch/openoffice/blob/af65e7a0e36b7536504695d9a46449da070a578c/vendor/rhwp-core/README.md) · [편집기 초기화](https://github.com/pblsketch/openoffice/blob/af65e7a0e36b7536504695d9a46449da070a578c/apps/hwp/src/renderer/App.tsx#L222-L253)

## 4. 기능 단위의 구현 순서와 완료 기준

| 단계 | 한 번에 확인할 작업 | 완료 기준 |
|---|---|---|
| R1 · 독립 실행 | 원본 저장소 루트에서 `npm run dev -w @genoffice/hwp`를 실행한다. | 한글 편집 창 하나가 열리고, 빈 A4 첫 문단에 커서가 놓인다. |
| R2 · 한글 작성 | 제목 `네트워크 실습 안내` 한 줄과 본문 두 문단을 실제 키보드로 입력한다. | 한글 조합 중 글자가 중복되거나 누락되지 않는다. Enter로 세 문단이 구분되고, 지운 글자를 실행 취소하면 원래 문장이 돌아온다. |
| R3 · HWPX 저장 | 문서를 `수업안내.hwpx`로 저장하고 독립 에디터에서 다시 연다. | 저장 전후의 제목, 본문 두 문단, 문단 순서가 정확히 같은지 자동 검사한다. |
| R4 · 원본 보호 | 문구 하나를 고쳐 `수업안내_수정.hwpx`로 저장한다. 미저장 상태에서 닫기도 시도한다. | 원본 파일의 바이트가 그대로이고 수정본에만 바뀐 문구가 있다. 닫기를 취소하면 작업 중인 문장이 남는다. |
| R5 · 외부 호환 | 저장한 파일을 한컴 한글에서 열고 한 문장을 고친 뒤 새 사본으로 저장한다. | 복구 안내 없이 열리고 한글·문단·A4 쪽 구성이 유지된다. 한컴에서 만든 사본을 독립 에디터로 열면 수정한 문장이 보인다. |

**첫 실습은 R1에서 마친다.** 단독 창에서 빈 문서가 열리고 첫 글자 `가`를 입력할 수 있는지 확인한다. **첫 시제품은 R5까지 통과했을 때 완성으로 본다.** R3은 자체 엔진이 쓴 파일을 다시 읽는 검사이고, R5는 교사가 학생에게 전달한 파일이 외부 프로그램에서도 편집되는지 확인하는 검사다.

## 5. 배포 시 확인할 사항

이음오피스·GenOffice에서 재사용하는 코드에는 Apache-2.0 라이선스 사본과 해당 출처 고지를 포함하고, 수정한 파일에는 변경 사실을 표시한다. rhwp에는 MIT 저작권·허가문을 동봉한다. 한컴 HWP 공개 규격 참조 문구는 독립 앱의 UI와 배포 문서에도 반영하고, 한자 사전을 포함할 경우 해당 사전의 고지를 함께 제공한다.
